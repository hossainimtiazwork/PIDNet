ANALYSIS: WHICH BRANCH (P, I, OR D) IS BEST?
================================================================================

Based on comprehensive analysis of the PIDNet code and paper:

SELECTED: I (Integral) Branch ✓

REASONING:
----------

1. ARCHITECTURAL PURPOSE:
   - P Branch: Detail preservation (local features, fine-grained details)
   - I Branch: Context embedding (global semantics, scene understanding)
   - D Branch: Boundary detection (edges, contours)

2. TASK REQUIREMENTS:
   View classification is a global task requiring:
   ✓ Overall scene understanding
   ✓ High-level semantic features
   ✓ Contextual information
   ✗ NOT local details (P branch specialty)
   ✗ NOT boundary information (D branch specialty)

3. TECHNICAL FACTORS:
   - I branch has deepest feature extraction (layer5)
   - I branch accumulates multi-scale contextual information
   - I branch processes features through complete network depth
   - Perfect alignment with global classification requirements

4. FEATURE EXTRACTION POINT:
   Selected: After layer5, before SPP module
   Rationale: Maximum semantic content, not yet spatially reduced

CONCLUSION: I (Integral) branch is the optimal choice for view classification
            based on architectural design, task requirements, and feature quality.

================================================================================
LOSS COMPUTATION
================================================================================

FORMULA:
--------
total_loss = loss_s + loss_b + loss_sb + VIEW_WEIGHT * loss_view

COMPONENTS:
-----------
- loss_s      : Semantic segmentation loss (P & final branches)
- loss_b      : Boundary loss (D branch)
- loss_sb     : Semantic-boundary combined loss
- loss_view   : View classification loss (I branch) [NEW]
- VIEW_WEIGHT : Configurable weight (default: 1.0, recommended: 0.5)

CONFIGURATION:
--------------
MODEL:
  NUM_VIEW_CLASSES: 4   # Number of view categories (0 disables feature)

LOSS:
  VIEW_WEIGHT: 0.5      # Weight for view classification loss
